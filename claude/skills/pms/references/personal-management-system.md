# 个人管理系统 / Personal Management System

本文档定义了个人管理系统的**分类、命名、同步、维护**规则。个人所有平台均遵循此文档要求。

> 语言约定：一级分类目录使用英文（kebab-case），中文仅作对照；文件命名与笔记内容保留中文。根目录统一为 `personal-management-system/`。

---

## 一、设计原则

1. **分类即标签** — 目录名即是分类，一看即知归属
2. **文件名自描述** — 脱离文件夹后只看文件名也能知道它是什么、什么时候的
3. **目录结构即同步策略** — 看一级目录名就知道该不该同步、同步到哪些设备
4. **规则少、可查、不靠记** — 所有规则写在这一份文档里

---

## 二、分类架构

十类按重要程度排列：根基 → 源头 → 主业 → 成长 → 工具 → 表达 → 保障 → 体验 → 扩展。

| 编号   | 英文目录名   | 中文对照   | 定位          | 示例内容       |
| ---- | ---- | ---- | ----------- | ---------- |
| `00` | identity | 个人档案 | 身份根基        | 证照学历、党籍    |
| `01` | education | 教育经历 | 学术源头        | XX大学       |
| `02` | career | 工作经历 | 职业经历        | XX公司       |
| `03` | notes | 笔记空间 | 日常积累        | 读书笔记、日常灵感  |
| `04` | references | 参考资料 | 知识库存        | 书籍、论文、工具手册 |
| `05` | writing | 思考创作 | 思想表达        | 博客、随笔、反思   |
| `06` | health | 健康医疗 | 身体底牌        | 体检报告、病历    |
| `07` | finance | 财务管理 | 经济保障        | 投资记录、保单    |
| `08` | life | 生活记录 | 人生体验        | 照片、旅行      |
| `09` | projects | 个人项目 | 个人扩展        | 个人作品、独立项目  |
| `99` | storage | 大型文件 | *(存储层，排最后)* | 视频、安装包、备份  |

### 关键约定

- **工作按公司分**：`02-career/` 下每家公司一个独立目录（公司名保留原名），雇佣人事（股权、绩效、报销）跟公司走。换工作时整个公司目录归档。
- **大文件分离**：`99-storage/` 为纯存储层，不属于分类体系，不参与同步。50MB 以上的文件放此处，在分类目录中用 `.link.md` 占位索引。

## 三、命名规范

### 3.1 目录命名

| 情况 | 规则 | 示例 |
|------|------|------|
| 十槽一级目录 | 固定英文名（中英对照见第二节） | `00-identity/` `03-notes/` |
| 有逻辑顺序 | `数字前缀-英文名` | `01-direction-a/` `02-direction-b/` |
| 日期分组 | `YYYY-MM` | `2022-12/` `2023-11/` |
| 独立容器 | 直接用名称；专有名词（公司名）保留原名 | `project-a/` `XX公司/` |

数字间隔使用 `01, 02, 05...`，方便未来在中间插入新类别。

### 3.2 文件命名

| 类型             | 规则                                         | 示例                        |
| -------------- | ------------------------------------------ | ------------------------- |
| **A. 自己产出的文档** | `YYYYMMDD-描述[-v版本].扩展名`                    | `20230715-项目进度跟踪.xlsx`    |
| **B. 下载的参考资料** | **按资料实际标题命名**（从 PDF 元数据或正文提取，不保留下载时的随机文件名） | `某领域综述2024.pdf`           |
| **C. 官方文件**    | **保留原名**（有法律效力，原名是身份一部分）                   | `张三-2024下半年绩效评价表-签名版.pdf` |
| **D. 代码项目**    | **不改**（遵循项目自身命名规范）                         |                           |

## 四、同步架构

### 4.1 同步链路

```
IMA ──► 个人设备 ──► 服务器 ──► 存储器
 │         |                    │
笔记（家里电脑/公司电脑等）   （定期冷归档）            
```

1. 个人设备从服务器按4.2所述从服务器拉取对应内容，个人设备上新增内容同步至服务器，个人设备间通过服务器同步；服务器定期将所有内容同步至存储器；
2. 链路上按4.3所述方式同步；

### 4.3 同步方式

1. **IMA → 个人设备**：手动触发同步，使用 `ima-skill` 和 `pms` 将笔记写入 `03-notes/` 同名子目录（IMA 笔记本名保留中文，与子目录按编号对应）
2. **个人设备 → 服务器**：定时触发同步（每日 19:00），推送全量
3. **服务器 → 个人设备**：手动触发同步
4. **服务器 → 存储器**：定期 rsync，冷归档


| 设备          | 同步内容                                   | 触发方式 | 同步方式                                                |
| ----------- | -------------------------------------- | ---- | --------------------------------------------------- |
| IMA -> 个人设备 | IMA所有笔记本同步至个人设备个人管理系统的`03-notes/`同名子目录下 | 手动   | AI使用使用 技能`ima-skill` 和 `pms` |
| 个人设备-> 服务器  | 个人设备个人管理系统下的所有内容同步至服务个人管理系统下           | 手动   | 使用rsync同步，windows下使用wsl rsync                       |
|             |                                        |      |                                                     |



### 4.4 公司电脑差异化

公司电脑仅同步：`02-career/`、`03-notes/`、`04-references/`。其余目录全部排除。

额外过滤（Syncthing Web UI → 忽略模式，仅公司电脑生效）：

```
*.mp4
*.iso
*.dmg
```

### 4.5 大文件处理

`99-storage/` 为纯存储层，不参与同步：

| 文件大小 | 放哪里 | 分类目录留什么 |
|----------|--------|---------------|
| < 50MB | 直接放对应分类目录 | 文件本身 |
| 50MB–500MB | `99-storage/` | `.link.md` 占位文件 |
| > 500MB | 移动硬盘 / NAS | `.link.md` 占位文件 |

所有同步工具排除 `99-storage/` 目录。

## 五、同步工具速查

| 工具 | 适用场景 | 特点 |
|------|----------|------|
| **Syncthing** | 公司 ↔ 家里 ↔ 服务器 | 点对点、无中心服务器、免费、数据不出机房 |
| **网盘客户端**（OneDrive / iCloud / 百度） | 个人多设备 | 有云端中转、跨平台客户端完善 |
| **Git** | 代码项目 | 版本管理，工作目录下的独立仓 |
| **rsync** | 服务器 ↔ 本地 | 一次性批量同步 |

选择建议：代码用 Git，文档用 Syncthing 或已有网盘，个人档案不同步。

### 5.1 WSL rsync 快速同步

Windows 本地无原生 rsync，通过 WSL 直接调用。

**前提**：SSH 密钥已部署到服务器（免密登录）。

**用法**（分两步，执行前确认目标）：

```powershell
# 1. 先 dry-run 预览
wsl rsync -avzh --dry-run --exclude-from=.rsyncignore `
  /mnt/c/<用户路径>/personal-management-system/ `
  <用户>@<服务器地址>:/<目标路径>/

# 2. 确认目标地址无误后，去掉 --dry-run 执行
wsl rsync -avzh --progress --exclude-from=.rsyncignore `
  /mnt/c/<用户路径>/personal-management-system/ `
  <用户>@<服务器地址>:/<目标路径>/
```

> 忽略规则定义在 `.rsyncignore` 文件中，与 `.gitignore` 用法类似。

## 六、日常操作指南

### 初始化

当 PMS 根目录（`personal-management-system/`）不存在时：

1. **从远程服务器导入** — 用 rsync 从服务器拉取（见 5.1），需用户提供服务器地址、用户名、目标路径
2. **将现有文件夹整理成 PMS 形式** — 用户指定一个文件夹，并勾选其中需要整理哪些子项（其余保持原样）；也支持指定其他文件夹。确认后创建 PMS 根目录、恢复 README，再按分类决策流程整理所选内容

### 启动健康检查

每次 skill 启动时检查 PMS 是否满足规范，发现问题按以下方式处理：

1. 十槽目录（`00-identity` ~ `09-projects`、`99-storage`）齐全 — 缺失的槽自动创建并提示
2. 一级目录为英文 kebab-case — 发现中文槽名（如 `03-笔记空间/`）提示用户并协助迁移
3. 根目录除 `README.md`、`.rsyncignore` 与十槽外无杂物 — 发现后按分类决策建议归属，用户确认后整理
4. `README.md` 与 skill 的 reference 一致 — 以修改时间较新的一方为准覆盖
5. `.rsyncignore` 存在 — 缺失时从 skill 的 references 恢复

### 新增内容

1. **定分类** — 属于哪个一级？哪个二级？三级要不要？
2. **命名** — 自己产出的：`YYYYMMDD-描述.扩展名`；下载的/官方的：保留原名
3. **放对位置** — 放入对应分类目录
4. **确认同步** — 检查是否放入了对应同步单元的目录

### 查找内容

- 按目录层级逐级进入，或直接 `find` / Spotlight 搜文件名

### 定期维护

- 每季度清理过期中间文件（如实验截图、临时导出数据）
- 每年归档一次不再活跃的项目（移入年份归档目录）
- 新增分类时更新本文档
- `00-identity/` 保持只增不减（身份文件永久保留）
