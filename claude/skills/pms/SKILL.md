# 个人管理系统 — Personal Management System

将用户的十槽分类体系、文件命名规范、同步策略应用于文件组织任务。

## 语言约定

- **根目录**：固定英文 `personal-management-system/`
- **一级分类目录（十槽）**：固定英文 kebab-case（`00-identity/` ~ `99-storage/`），中文仅作对照（见 reference 分类架构表）
- **子目录**：有逻辑顺序用 `数字前缀-英文名`（如 `01-direction-a/`）；专有名词（公司名等）保留原名；日期分组用 `YYYY-MM`
- **文件名与笔记内容**：保留中文，不翻译

## 启动检查

### 1. 根目录探测

每次被调用时，先探测 PMS 根目录（`personal-management-system/`）是否存在：

- **存在** → 进入第 2 步「PMS 健康检查」
- **不存在** → 询问用户初始化方式：
  - **从远程服务器导入**：按第六节规则用 rsync 从服务器拉取（需用户提供服务器地址、用户名、目标路径）
  - **将现有文件夹整理成 PMS 形式**：询问用户要整理哪个文件夹，并列出该文件夹下的内容让用户勾选哪些子项需要纳入整理（其余保持原样不动）；也支持用户另行指定其他文件夹
  - 用户确认后，创建 PMS 根目录，按分类决策流程整理所选内容；整理完成后根据**实际结构**生成 README（skill 是初始模板，README 是系统结构的实时说明）

### 2. PMS 健康检查

根目录存在（或初始化完成）后，逐项检查是否满足 skill 要求：

1. **十槽目录齐全**：`00-identity` ~ `09-projects`、`99-storage` 应全部存在。缺失的槽直接创建并提示用户（十槽为固定框架，补齐无副作用）
2. **一级目录命名规范**：不应出现中文槽名（如 `03-笔记空间/`）。发现时提示用户，协助迁移为英文
3. **根目录无杂物**：除 `README.md`、`.rsyncignore` 与十槽目录外，根目录出现的其他文件/目录 → 按分类决策流程建议归属，用户确认后整理
4. **README 反映实际结构**：README 是当前系统结构的实时说明。缺失或与实际结构不符 → 根据实际结构重新生成（不从 skill 的 reference 复制）。skill 的 reference 是初始模板，仅在从零初始化时使用，不随 README 变化自动更新

5. **`.rsyncignore` 存在**：缺失 → 从 skill 的 references 恢复

全部通过 → 继续执行任务。发现问题时：1、4、5 项可直接修复并提示；2、3 项需用户确认后处理。

## IMA 笔记同步

当用户要求将 IMA 笔记同步到 PMS 时，执行以下规则：

1. **调用 ima-skill** 读取 IMA 全部笔记（按笔记本分组）
2. **笔记本命名遵循 PMS 规范**：IMA 笔记本名保留中文（`数字前缀-名称`），与 `03-notes/` 下同名子目录一一对应，本地不存在则创建
3. **笔记命名遵循 PMS 规范**：A 类（自己产出）加 `YYYYMMDD-` 日期前缀，C 类（官方/信息记录）保留原名，正文内容完全保留
4. **本地独有目录**（如 `代码开发`、`工具命令`、`环境配置`）不在 IMA 笔记本中，同步时不覆盖、不删除

## 核心职责

1. **分类决策** — 当用户给出一个文件或内容描述时，判断它应该放在哪个分类
2. **命名检查** — 检查文件名是否符合 `YYYYMMDD-描述.扩展名` 规范，不符合的给出建议
3. **同步建议** — 根据内容敏感度，建议应该同步到哪些设备
4. **架构合规** — 新增内容时确保不破坏现有的十槽分类结构

## 分类决策流程

收到一个文件或内容描述时，按以下顺序判断归属：

```
它是官方证件/证书/党员材料？
  → 00-identity（个人档案）

它是本科/硕士阶段的学术成果（论文、课程项目、竞赛）？
  → 01-education（教育经历）

它是当前/过去工作相关的内容？
  → 02-career（工作经历，然后在下面按公司分）

它是各类笔记：环境配置、编程、AI-ML、论文研究、工作日志等？
  → 03-notes（笔记空间）

它是自己写的文章、博客、反思？（非商业）
  → 05-writing（思考创作）

它是论文/学术参考资料？
  → 04-references/02-papers（用子目录关联工作上下文，如 papers/时序布局/、papers/LeDSE/）

它是书籍/工具手册？
  → 04-references（参考资料，按子类分）

它是医疗相关的（体检报告、病历、保险）？
  → 06-health（健康医疗）

它是财务相关的（投资、保单、税务）？
  → 07-finance（财务管理）

它是生活体验记录（照片、旅行、日常）？
  → 08-life（生活记录）

它是个人项目、独立作品？
  → 09-projects（个人项目）

它是大于 50MB 的大文件？
  → 99-storage（大型文件，存储层，不参与同步，在分类目录放 .link.md 占位）
```

## 命名规范

### 文件（自己产出的）
```
YYYYMMDD-描述[-v版本].扩展名
```

### 文件（下载的参考资料）
根据资料实际标题命名，不保留下载时的随机文件名。优先从 PDF 元数据或正文提取标题。
示例：`SykdfdRlrLPEQBBX.pdf` → `PrimeTime User Guide - v2016.06.pdf`

### 文件（官方/代码）
保留原名，不重命名。官方文件有法律效力，原名是身份的一部分。代码遵循项目自身命名规范。

### 目录
- 十槽一级目录：固定英文名（`00-identity/` 等），中英对照见 reference 分类架构表
- 有逻辑顺序的：`数字前缀-英文名`，如 `01-direction-a/`
- 独立容器的：直接用名称，专有名词保留原名，如 `project-a/`、`XX公司/`
- 日期分组的：`YYYY-MM`，如 `2023-11/`

## 同步建议

| 分类 | 同步策略 |
|------|----------|
| 00-identity（个人档案） | 不同步，仅本地 |
| 01-education（教育经历） | 全设备（只读归档） |
| 02-career（工作经历） | 公司+家里+服务器 |
| 03-notes（笔记空间） | 全设备 |
| 05-writing（思考创作） | 全设备 |
| 04-references（参考资料） | 全设备（视频仅家里+服务器） |
| 06-health（健康医疗） | 不同步，仅本地 |
| 07-finance（财务管理） | 不同步，仅本地 |
| 08-life（生活记录） | 全设备 |
| 09-projects（个人项目） | 按项目决定 |

## 输出格式

当用户询问文件归属时，回复结构：

1. **建议分类路径**：`XX-英文分类名/子目录/文件名`（如 `03-notes/代码开发/20260829-环境配置.md`）
2. **建议命名**（如果原名不符合规范）
3. **同步建议**：应同步到哪些设备
4. **备注**：任何需要注意的边界情况

## 维护规则

**结构变更时更新 README。** 当 PMS 目录结构发生变化（新增/改名/删除分类目录、调整归属）时，同步更新 README，保持与实际结构一致。

**提交前检查同步。** 当用户明确表示要提交/同步当前修改时，检查改动是否涉及以下内容：

- 十槽分类体系（目录结构、命名）
- 文件命名规范
- 同步策略
- 跨平台映射规则

如果涉及上述内容，**必须先提示用户确认**再执行，提示语：

> 本次修改涉及 [分类体系/命名规范/同步策略]，README 已随结构同步更新。是否需要将变更同步进 Skill（初始模板）并提交到服务器？

用户在运行时提供：服务器地址、用户名、目标路径。

**同步前强制确认**：执行 rsync 前，必须向用户展示拼接后的完整目标地址，并请用户二次确认，格式：

> 即将同步到：`<用户>@<服务器地址>:/<目标路径>/`
> 确认无误？

用户明确确认后才执行。dry-run 和正式执行都需要此确认步骤。
